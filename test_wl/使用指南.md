# 📘 如何使用AI_IDE代码库分析提示词模板

## 🎯 用途

`AI_IDE代码库分析提示词模板.md` 是一个**通用模板**，用于指导AI IDE为深度学习代码库创建全面的学习指南。它从优秀的FlashOCC指南中提炼而来。

## 🚀 快速开始

### 步骤1：复制提示词

开始分析新仓库时（如BEVFormer、Dreamer、RT-2），粘贴以下内容：

```
我想为这个代码库创建完整的掌握指南。

请严格遵循 @AI_IDE代码库分析提示词模板.md 中的模板。

领域：[选择：自动驾驶 / 具身智能 / VLA / 世界模型 / 端到端学习]
目标时间：4-6小时专注学习
深度：可实现级别的理解

从第0章开始：完整继承链分析。

重要提示：
1. 遵循所有自我验证协议。用代码引用验证每个声明。
2. 所有输出必须使用中文
3. 代码注释使用中文
4. 技术术语首次出现时双语标注：中文（English）
```

### 步骤2：监控进度

AI应该：
1. ✅ 在`test_wl/`目录创建结构化文档
2. ✅ 遵循3轮修订流程
3. ✅ 需要时请求PDF分析（你将用外部工具协助）
4. ✅ 主动自我修正错误

### 步骤3：质量检查

AI完成后，验证：
- [ ] 所有文件路径和行号准确
- [ ] 数值示例计算正确
- [ ] 无通用陈述（一切都是仓库特定的）
- [ ] 存在带答案的自测题
- [ ] 对比文档与2-4个相关方法对比
- [ ] **所有内容使用中文**

## 🎓 模板的特色

### 1. **防幻觉强制措施**
- 每个声明必须引用`file.py:行号`
- 每个形状必须用具体维度验证
- 红旗："可能"、"似乎"、"看起来"
- 修复：标记不确定 → 验证 → 更新或删除

### 2. **领域专用检查清单**
- **自动驾驶**：坐标系、BEV、多相机、深度
- **具身智能**：动作/观测空间、策略、sim2real
- **VLA**：多模态融合、指令基础、动作解码
- **世界模型**：状态表示、动力学、规划
- **端到端**：输入/输出空间、训练范式、安全

### 3. **教学结构**
- 导师人设解释（先为什么后是什么）
- 时间估计（⏱️）和难度（⭐⭐⭐）
- 每个主要部分后有自查问题
- 带具体值的数值示例
- 记忆辅助和类比
- **全程使用中文教学**

### 4. **对比框架**（横向对比）
- 与2-4个相关方法并排对比表
- "何时使用每个"指南
- 演进时间线（mermaid图）
- 关键洞察和经验教训

### 5. **版本演进**（纵向对比）
- V1→V2→V3改变了什么
- 每次改变的原因（性能/简单性/部署）
- 用户迁移指南

### 6. **作业系统**（课后自测）
- 30题横跨3个难度级别
- 架构（10）+ 算法（10）+ 实现（10）
- 带详细解释的答案
- 及格分数：80%

## 🔄 3轮流程

### 第1轮：初稿
- AI写完所有章节0-5
- 包含代码引用（粗略也行）
- 基本图表和每个算法一个数值示例

### 第2轮：准确性扫描
- AI重新验证每个代码引用
- 重新计算每个形状
- 搜索代码库验证每个声称的功能
- 用`⚠️ 已验证`标记已验证声明

### 第3轮：教学增强
- 添加导师解释
- 插入自查问题
- 改进图表
- 完成作业和FAQ文档
- **确保全程中文**

## 📖 PDF分析工作流

当AI遇到需要分析的论文时：

**AI会停下来说**：
```
⚠️ 需要PDF分析

我需要：[论文名称]
重点：[具体章节]
所需信息：[要提取什么]

请使用外部AI工具提取并粘贴到这里。
```

**你要做**：
1. 将论文内容复制到Claude/GPT/Kimi
2. 询问："提取算法章节、数学公式和与代码的关键差异"
3. 将响应粘贴回IDE
4. AI继续对比（论文vs代码）

## ✅ 质量指标

### 好的迹象
- ✅ 每个算法都有：数学 + 代码（文件:行号）+ 数值示例
- ✅ 每步都验证形状（B=2, N=6, H=128, W=352 → ...）
- ✅ 对比表填充了真实数字
- ✅ 自测有30题及答案
- ✅ 无模糊语言（"可能"、"似乎"）
- ✅ **全部使用中文**

### 红旗
- ❌ 通用描述（"提取特征"、"做融合"）
- ❌ 缺少行号或错误文件路径
- ❌ 形状与维度不匹配（如4x4矩阵乘以3D向量）
- ❌ 无代码证据的声明
- ❌ 对比中有"未知"或"N/A"值
- ❌ **使用英文输出**

## 🛠️ 定制技巧

### 针对你的特定需求

**如果想在某些主题上更深入**：
```
在第2章（算法深度剖析）中，在以下方面花更多时间：
- [算法X]：包含3个数值示例而非1个
- [算法Y]：添加伪代码演练
```

**如果想在某些部分更简略**：
```
第4章（数据管道）可以更短，因为我熟悉数据加载。
只关注仓库特定的增强技术。
```

**如果想特定对比**：
```
在算法横向对比.md中，必须与以下对比：
1. [方法A] - 关注架构差异
2. [方法B] - 关注性能权衡
3. [方法C] - 关注实现复杂度
```

**语言要求强调**：
```
重要：所有文档必须使用中文
- 章节标题、正文、解释全部中文
- 代码注释中文
- 技术术语首次出现双语标注
```

## 🌐 语言使用重要提示

### 为什么必须使用中文

1. **学习效率**：母语学习理解更快、更深
2. **记忆留存**：中文记忆比外语更持久
3. **应用能力**：中文思考更利于实际应用
4. **团队协作**：便于与国内团队分享

### 如何确保中文输出

**在每次启动命令中明确**：
```
重要提示：
1. 所有输出必须使用中文
2. 代码注释使用中文
3. 技术术语首次出现时双语标注：中文（English）
4. 章节标题、正文、解释全部中文
```

**验证AI输出**：
- [ ] 章节标题是中文
- [ ] 正文解释是中文
- [ ] 代码注释是中文
- [ ] 图表标注是中文
- [ ] 只有变量名/函数名保持英文

**示例对比**：

**正确** ✅：
```markdown
## 第2章：可变形注意力机制（Deformable Attention）

可变形注意力是对标准注意力的改进，通过学习采样偏移来减少计算量。

### 2.1 核心思想

不同于标准注意力计算所有位置的权重，可变形注意力只在少量关键位置采样...
```

**错误** ❌：
```markdown
## Chapter 2: Deformable Attention

Deformable attention is an improvement over standard attention...
```

### 🤔 为什么分成两个文件？

#### 设计理由：

1. **关注点分离**：
   - AI指令 vs 人类指令
   - 要创建什么 vs 如何使用创建的内容

2. **不同使用模式**：
   - AI：每次仓库分析读一次
   - 你：多次参考（之前、期间、之后）

3. **更易维护**：
   - 更新AI要求 → 只编辑AI_IDE代码库分析提示词模板.md
   - 添加用户技巧 → 只编辑使用指南.md
   - 无混淆AI与面向用户内容的风险

4. **更好组织**：
   - AI_IDE代码库分析提示词模板.md：密集、全面、正式
   - 使用指南.md：简洁、示例丰富、友好
