## ✅ 改进后（叙事优先 + 逻辑连贯）

### 2.1 递归时序融合（Sparse4D v2核心）

---

### 📖 章节导读

**🎬 故事背景**：

想象你正在开发一个自动驾驶系统。你的系统现在能识别当前帧的车辆，但是存在严重问题：

1. **视频抖动问题**：前一帧检测到一辆车在(10m, 5m)，下一帧突然跳到(12m, 6m)，再下一帧又跳回(10.5m, 5.2m)
2. **遮挡问题**：当车辆被遮挡时，检测结果消失，遮挡结束后又重新出现，系统无法知道是同一辆车
3. **轨迹预测需求**：要预测其他车的轨迹，你需要知道它们的历史运动信息

解决方案很直观：**使用多帧信息！**

但Sparse4D v1的做法是：缓存过去9帧的完整图像特征图
- 内存占用：9帧 × 6相机 × 4尺度 × (B, C=256, H, W) ≈ **1.2GB**
- 推理速度：每帧都要对9帧图像特征进行采样，FPS只有**6.1**

**核心矛盾**：需要长时序信息（提升精度）vs 内存/速度限制（工程可行性）

**💡 v2的核心洞察**：

我们真的需要保存**完整的图像特征**吗？其实我们只关心**高置信度的检测结果**！

- v1思路：保存图像 → 每次从图像中采样特征
- v2思路：保存高质量的检测结果 → 直接使用历史检测

类比：就像看视频，你不需要记住每一帧的每个像素，你只需要记住"有一辆白色丰田在左侧车道行驶"这个高层信息。

**📍 在系统中的位置**：

```

[已完成] DataLoader → [已完成] 图像编码 → [已完成] 特征提取 →

```

### 🔍 WHY - 为什么需要递归时序融合？

**不用这个算法会怎样？**

问题1：**检测抖动**
- 现象：同一辆车的检测框在相邻帧之间位置跳跃
- 影响：无法进行稳定跟踪，MOT指标（AMOTA）从0.42降到0.18
- 根本原因：单帧检测容易受噪声影响

问题2：**遮挡敏感**
- 现象：被遮挡时检测消失，ID丢失
- 影响：跟踪轨迹断裂，IDS（ID切换）指标增加300%
- 根本原因：单帧无法利用历史信息推断被遮挡物体

问题3：**无法预测轨迹**
- 现象：不知道其他车辆的历史运动
- 影响：无法预测未来轨迹，影响规划模块
- 根本原因：缺少时序建模

**历史方案的局限**：

**方案A：Sparse4D v1（多帧特征采样）**
- 做法：缓存T=9帧的图像特征图，每次从9帧中采样
- 优点：精度高，mAP=0.439
- 缺点：
  - 内存：9帧 × 6相机 × 4尺度 = **1149MB显存**
  - 速度：复杂度O(T·M·K·N·S)，FPS=**6.1**（无法实时）
  - 可扩展性：帧数每增加1，内存增加128MB

**方案B：光流对齐（BEVDet）**
- 做法：用光流将历史帧对齐到当前帧
- 优点：速度快，FPS=15
- 缺点：
  - 光流在大运动时不准确，mAP=0.412（低7% mAP）
  - 需要额外的光流估计网络

**为什么现有方案不够好？**

根本问题：**信息冗余**

想想看，一帧1920×1080的图像有200万像素，但我们真正关心的是什么？是那几十个检测框！
每个检测框只需要256维特征 + 11维位置，总共不到1KB。

但传统方法保存的是完整图像特征图（几百MB），这就像为了记住"桌上有个苹果"，
你把整个桌子的每个原子都记下来——完全没必要！

递归融合就是聪明的做法：**只记住重要的检测结果，丢弃冗余的图像信息**。

### 🎯 WHAT - 核心功能是什么？

**一句话概括**：

递归时序融合通过**缓存高置信度实例而非图像特征**，实现了**O(1)复杂度的多帧融合**，
使得内存从1149MB降至432MB（-62%），FPS从6.1提升至15.3（+2.5倍），同时mAP从0.439提升至0.469（+3% mAP）。

**功能分解**（三个子功能）：

1. **运动补偿投影**：将历史锚框从t-1坐标系投影到t坐标系
   - 为什么需要？因为ego车在移动，历史车辆的坐标需要更新
   - 输入：(B, 600, 11) + ego运动矩阵(B, 4, 4)
   - 输出：(B, 600, 11)
   - 代码：`instance_bank.py:L98-111`

2. **递归融合**：将[历史600 + 当前Top-300]拼接成900个候选
   - 为什么需要？融合历史和当前信息，提升时序稳定性
   - 输入：历史(B, 600, 256+11) + 当前(B, 900, 256+11)
   - 输出：融合(B, 900, 256+11)
   - 代码：`instance_bank.py:L146-186`

3. **缓存更新**：从900个候选中选Top-600保存到缓存
   - 为什么需要？下一帧需要这600个高质量实例
   - 输入：(B, 900, 256+11) + 置信度(B, 900)
   - 输出：Top-600 → self.cache
   - 代码：`instance_bank.py:L188-214`

**关键设计决策**：

Q：为什么是600 + 300 = 900，而不是其他组合？
A：Trade-off的结果
- 600太少：历史信息不足，时序稳定性差
- 300太少：当前信息不足，无法检测新出现的物体
- 900太多：计算量大，Decoder处理慢
- 实验发现：600:300是最优比例（参见论文Table 3）

Q：为什么缓存600个而不是全部900个？
A：内存和速度的trade-off
- 600个：432MB显存，满足工程需求
- 900个：648MB显存，增益有限（mAP只提升0.002）

Q：为什么用置信度衰减（×0.6）？
A：时间越久，信息越不可靠
- 0.5s前的检测：置信度×0.6
- 1.0s前的检测：置信度×0.36
- 1.5s前的检测：置信度×0.216
- 这样旧的检测会逐渐被新检测替换

#### 代码段1：运动补偿投影

**这段代码在解决什么问题？**

上一帧检测到一辆车在位置(10, 5, 0)m，速度(5, 0, 0)m/s。
经过0.5秒后，这辆车应该在哪里？

如果ego车静止：简单，车应该在(10 + 0.5×5, 5, 0) = (12.5, 5, 0)

但ego车也在移动！假设ego车向前开了2m，向右转了5°。
那么相对于**当前ego车**，这辆车应该在哪？

这就是运动补偿要解决的：**从"相对于旧ego车的坐标"转换为"相对于新ego车的坐标"**。

**数学公式（回顾）**：
$$
\mathbf{p}_t = R_{t-1 \rightarrow t} \cdot (\mathbf{p}_{t-1} + \Delta t \cdot \mathbf{v}_{t-1}) + \mathbf{T}_{t-1 \rightarrow t}
$$

步骤：
1. 物体运动：$\mathbf{p}_{t-1} + \Delta t \cdot \mathbf{v}_{t-1}$（车自己在动）
2. 坐标旋转：$R_{t-1 \rightarrow t} \cdot (...)$（ego车转向）
3. 坐标平移：$... + \mathbf{T}_{t-1 \rightarrow t}$（ego车位移）

**输入输出**：
- 输入1：`self.cached_anchor` (B, 600, 11) - 上一帧的锚框，坐标在旧ego坐标系
- 输入2：`T_global` (B, 4, 4) - ego运动变换矩阵
- 输入3：`time_interval` (B,) - 时间间隔，如0.5秒
- 输出：`projected_anchor` (B, 600, 11) - 投影到当前ego坐标系的锚框

**真实代码**：

```python
# 文件: projects/mmdet3d_plugin/models/instance_bank.py
# 行号: 98-111

# 步骤1：计算ego运动变换矩阵 T_{t-1→t}
T_temp2cur = self.cached_anchor.new_tensor(
    np.stack([
        # 对批次中的每个样本
        x["T_global_inv"] @ self.metas["img_metas"][i]["T_global"]
        for i, x in enumerate(metas["img_metas"])
    ])
)  # → (B, 4, 4)

# 💡 为什么这样计算？
# T_{t-1→t} = T_t^{-1} · T_{t-1}
# 含义：先从t-1坐标系转到世界坐标系（乘T_{t-1}）
#       再从世界坐标系转到t坐标系（乘T_t^{-1}）

# 步骤2：执行锚框投影（包含物体运动 + ego运动）
self.cached_anchor = self.anchor_handler.anchor_projection(
    self.cached_anchor,      # (B, 600, 11) - 待投影的锚框
    [T_temp2cur],            # List[(B, 4, 4)] - 变换矩阵列表
    time_intervals=[-time_interval],  # (B,) - 时间间隔
)[0]  # 返回List[(B, 600, 11)][0] → (B, 600, 11)

# 💡 为什么time_interval是负数？
# 正数：从现在预测未来（time_interval=0.5 表示预测0.5秒后）
# 负数：从过去投影到现在（time_interval=-0.5 表示从0.5秒前投影）
# 这里是"从t-1投影到t"，方向是"过去→现在"，所以用负数

# 💡 anchor_projection内部做了什么？（简化版）
def anchor_projection(anchor, transforms, time_intervals):
    # 1. 分解锚框
    pos = anchor[..., :3]      # (B, N, 3) - [x, y, z]
    vel = anchor[..., 8:11]    # (B, N, 3) - [vx, vy, vz]
    
    # 2. 物体运动
    pos_moved = pos + time_intervals[..., None] * vel
    
    # 3. 坐标变换（旋转+平移）
    pos_transformed = apply_transform(pos_moved, transforms)
    vel_transformed = rotate_velocity(vel, transforms)
    
    # 4. 重组锚框
    return reassemble_anchor(pos_transformed, vel_transformed, ...)
```

**🔍 逐行解读**：

L98-102：计算ego运动矩阵
- 为什么需要？车辆位置是相对坐标，ego车动了就要更新
- 如何计算？通过全局坐标作为桥梁：局部→全局→新局部
- 数学依据：$T_{A \rightarrow C} = T_C^{-1} \cdot T_A$

L104-111：投影锚框
- 为什么需要？11维锚框不是单纯的点，还包含尺寸、方向、速度
- 内部细节：
  - 位置投影：$\mathbf{p}' = R(\mathbf{p} + \Delta t \mathbf{v}) + \mathbf{t}$
  - 方向旋转：$[\cos\theta', \sin\theta']^T = R [\cos\theta, \sin\theta]^T$
  - 速度旋转：$\mathbf{v}' = R \mathbf{v}$
  - 尺寸不变：$[w, l, h]' = [w, l, h]$

**🔢 数值示例**（具体计算）：

```
- 上一帧（t-1）检测到车A：位置(10, 5, 0)m，速度(5, 0, 0)m/s
- 时间间隔：Δt = 0.5s
- ego运动：向前2m，向右转5°

步骤1：物体自身运动
pos_moved = (10, 5, 0) + 0.5 × (5, 0, 0)
          = (12.5, 5, 0)

步骤2：构建变换矩阵 T_{t-1→t}
ego向前2m、右转5° → R = [cos(5°) -sin(5°) 0]
                           [sin(5°)  cos(5°) 0]
                           [0        0       1]
                     T = [-2, 0, 0]

步骤3：应用变换
pos_transformed = R · (12.5, 5, 0) + T
                = [cos(5°)×12.5 - sin(5°)×5, sin(5°)×12.5 + cos(5°)×5, 0] + [-2, 0, 0]
                ≈ [12.46 - 0.44, 1.09 + 4.98, 0] + [-2, 0, 0]
                = [10.02, 6.07, 0]

结论：相对于当前ego车，车A在(10.02, 6.07, 0)m
```

**常见错误**：

❌ 错误1：忘记物体自身运动
```python
# 错误代码
pos_transformed = apply_transform(pos, T)  # 没有加上 Δt·v
```
- 后果：静态物体正确，运动物体位置错误
- 现象：车辆"瞬移"，轨迹不连续

❌ 错误2：时间间隔符号错误
```python
# 错误代码
time_intervals=[time_interval]  # 应该是负数
```
- 后果：投影方向相反，车辆位置镜像错误
- 调试线索：检测框在ego车对称位置出现
